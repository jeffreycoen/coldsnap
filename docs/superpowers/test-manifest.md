# COLDSNAP — Test census and keep/prune recommendations

*Written 2026-08-11 for Phase C0 Task 1 (mk0.30). **Nothing has been deleted.** Every verdict below is a recommendation for Jeff to review. Task 2 executes only what he returns.*

**The law these verdicts apply.** Automated tests exist to prove things *load* — the page mounts, each mode starts, the version string is on screen, nothing errors in the console. Scripted play-throughs, bot-completions, and "does the game behave this way" assertions are PRUNE by default: they are slow, they go stale every time the design moves, and they cry wolf. Two gates are kept no matter what: `golden.mjs`, which proves the demo's physics still matches the frozen original exactly, and `depot-lint.mjs`, which proves no unseeded randomness has crept into the depot code. Cheap headless checks of pure functions and data contracts (no browser, no play) are judged one at a time. Measuring tools are not tests at all — they are marked KEEP-AS-DIAG, meaning kept on disk for measurement and kept out of the deploy pipeline.

**Verdict words.** KEEP = leave as is. TRIM = keep the file but cut the listed part. PRUNE = delete. KEEP-AS-DIAG = not a test; keep the file, never run it in the pipeline.

**Where things run today.** The deploy pipeline (`.github/workflows/deploy.yml`) runs eleven headless checks and then builds. The browser suite (`scripts/smoke.mjs`) and the two tower-defence browser checks never run in the pipeline — they need a live server, so they are local-only. Everything with no `npm` entry and no pipeline line is marked **orphan**: nothing invokes it but a person typing the filename.

**About the runtimes.** Only `golden.mjs` was actually timed for this census (24 seconds on the Pi). Everything else is an estimate read off the file's structure — how many worlds it builds, how many simulated seconds it steps, whether it drives a browser. Pipeline machines run roughly three times faster than the Pi. The browser suite takes somewhere between 10 and 20 minutes end to end on the Pi under the software renderer; the per-section browser figures below are Pi minutes and should be read as rough shares of that, not measurements.

### `smoke.mjs` — the browser suite (1380 lines)

**Shared infrastructure (read before cutting).** Three helpers live at the top and are used by every section: `sleep`, `clickMenu` and `text` (lines 36-51), plus the shared browser page, the page-error collector and the final "no page errors during the run" assert (lines 37-57 and 1369-1380). Those must survive any pruning. The one big section-local helper, `seedMission` (line 343), is defined inside and used only by the campaign section — it leaves with that section and orphans nothing.
